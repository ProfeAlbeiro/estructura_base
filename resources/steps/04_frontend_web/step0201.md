## 1.1. ¿Qué es React?

#### 1.1.1. Definición oficial

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **React** es una **biblioteca de JavaScript** para construir **interfaces de usuario** a partir de **componentes**.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Fue creada por **Facebook (Meta)** en 2013 y hoy es mantenida por Meta + una comunidad enorme.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **No es un framework completo** (no trae router, ni formularios, ni HTTP). Es la **V** de una arquitectura MVC. Por eso en nuestro proyecto usamos `react-router-dom` aparte para las rutas.

#### 1.1.2. ¿Qué significa "biblioteca de interfaces"?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Significa que React se encarga **solo** de una cosa: **convertir datos en HTML visible**.

```
Datos (estado)  ───►  React  ───►  HTML en pantalla
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Cuando los datos cambian, React **actualiza el HTML automáticamente**. Usted no tiene que decirle al navegador *"borra este `<div>` y crea otro"* — React lo hace por usted. Eso se llama **renderizado declarativo**.

#### 1.1.3. React en una sola frase

> **"Usted describe cómo debe verse la interfaz para un estado dado, y React se encarga de mantener el DOM sincronizado con ese estado."**

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Compare con el enfoque **imperativo** (JS clásico):

```javascript
// JS clásico (imperativo): "haz esto, luego aquello"
const titulo = document.getElementById('titulo')
titulo.textContent = 'Hola'
titulo.style.color = 'red'
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Con React (declarativo):

```jsx
// React (declarativo): "así debe verse cuando el estado es este"
function Titulo({ texto }) {
  return <h1 style={{ color: 'red' }}>{texto}</h1>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; La diferencia no es solo sintáctica: en React **usted nunca toca el DOM directamente**. Solo dice *qué* mostrar y React decide *cómo* hacerlo.

## 1.2. ¿Por qué React y no HTML/JS puro?

#### 1.2.1. Problema del enfoque clásico

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Imagine un formulario de login en HTML + JS "puro". Cuando el usuario envía el formulario, usted tiene que:

1. Leer el valor del `<input>` con `document.querySelector`.
2. Validar el email a mano.
3. Mostrar un spinner de carga → **crear un `<div>` nuevo**.
4. Si hay error → **insertar otro `<div>`**.
5. Si hay éxito → **ocultar el formulario y mostrar el dashboard**.
6. Al cerrar sesión → **volver a construir el formulario desde cero**.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Son **6 pasos imperativos** y en cada uno usted puede olvidar limpiar un `addEventListener`, o dejar un `<div>` huérfano en el DOM.

#### 1.2.2. Ventajas de React

| Problema clásico                                | Cómo lo resuelve React                                    |
| ----------------------------------------------- | --------------------------------------------------------- |
| Muchos `document.getElementById` dispersos      | Usted describe el HTML final, React actualiza el DOM      |
| Estado de la UI disperso en variables sueltas   | Todo el estado vive en `useState` (un solo lugar)         |
| Repetir HTML una y otra vez                     | Los componentes se **reutilizan**                         |
| Difícil testear la lógica de UI                 | Los componentes son funciones puras → fáciles de testear  |
| Migrar de API falsa a real rompe la UI          | Si la UI depende del estado, solo cambia el origen del estado |

#### 1.2.3. ¿Y por qué no Angular o Vue?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Angular** es un framework completo (opina sobre todo: router, HTTP, formularios). Curva de aprendizaje alta, TypeScript obligatorio.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Vue** es intermedio: más simple que Angular, menos ecosistema que React.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **React** es el más usado en la industria, el que más ofertas de trabajo tiene, y su modelo mental (componentes + estado) es **el mismo** que usan React Native (móvil) y frameworks modernos como Next.js.

## 1.3. La mentalidad de componentes

#### 1.3.1. ¿Qué es un componente?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Un **componente** es una **función de JavaScript** que:

1. **Recibe** datos de entrada (llamados **props**).
2. **Devuelve** un fragmento de interfaz (JSX, que se ve como HTML).
3. Tiene un **nombre con mayúscula inicial** (obligatorio).

```jsx
function Saludo({ nombre }) {
  return <h2>Hola, {nombre}</h2>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Ese componente se puede **usar como si fuera una etiqueta HTML**:

```jsx
<Saludo nombre="María" />
<Saludo nombre="Pedro" />
<Saludo nombre="Ana" />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Cada uso del componente **renderiza un `<h2>` independiente**. Esto es lo que se llama **reutilización**.

#### 1.3.2. La regla de oro

> **"Si una parte de la interfaz se repite, se hace componente. Si una parte de la interfaz tiene su propio estado, se hace componente. Si una parte de la interfaz es lo bastante compleja como para merecer un nombre, se hace componente."**

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **No existe un tamaño "correcto"** de componente. Un componente puede ser una sola línea (`<LoadingSpinner />`) o cientos de líneas (un dashboard completo).

#### 1.3.3. Árbol de componentes

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Toda aplicación React es un **árbol** de componentes. El componente de arriba se llama **raíz** (root).

```
App (raíz)
├── Navbar
├── LoginView
│   ├── AlertMessage
│   └── LoadingSpinner
└── DashboardView
    ├── DashboardHeader
    ├── DashboardStats
    └── UsersView
        ├── UserForm
        └── UserDetails
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Cada caja del árbol es un archivo `.jsx` en `src/views/` de nuestro esqueleto del Paso 3.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Los componentes **se componen** unos dentro de otros. Por eso React se llama "React": porque permite **componer** UI a partir de piezas.

## 1.4. Anatomía de un componente

#### 1.4.1. Estructura mínima

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Todo componente funcional tiene **tres partes**:

```jsx
// 1. Declaración (función con mayúscula)
function MiComponente(props) {
  // 2. Lógica (opcional): cálculos, estado, efectos
  const mensaje = 'Hola'

  // 3. Retorno: JSX (lo que se ve en pantalla)
  return (
    <div>
      <h1>{mensaje}</h1>
      <p>{props.descripcion}</p>
    </div>
  )
}

// 4. Exportación (para poder importarlo desde otro archivo)
export default MiComponente
```

| Parte            | ¿Qué hace?                                        | ¿Obligatoria? |
| ---------------- | ------------------------------------------------- | ------------- |
| **Declaración**  | Define la función con mayúscula inicial           | ✅ Sí          |
| **Lógica**       | Variables, hooks (`useState`, `useEffect`…)       | ❌ No          |
| **Retorno JSX**  | Devuelve **un solo** elemento raíz                | ✅ Sí          |
| **Exportación**  | Permite importarlo desde otro archivo             | ✅ Sí          |

#### 1.4.2. Reglas inquebrantables

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Regla 1:** el nombre del componente **empieza con mayúscula**. `loginView` ❌, `LoginView` ✅.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Regla 2:** el `return` devuelve **un solo elemento raíz**. Si necesita varios, envuélvalos en un `<div>` o en un **fragmento** `<>…</>`.

```jsx
// ❌ Incorrecto: dos elementos raíz
return (
  <h1>Título</h1>
  <p>Texto</p>
)

// ✅ Correcto: un solo elemento raíz
return (
  <div>
    <h1>Título</h1>
    <p>Texto</p>
  </div>
)

// ✅ También correcto: fragmento (no genera <div> extra en el DOM)
return (
  <>
    <h1>Título</h1>
    <p>Texto</p>
  </>
)
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Regla 3:** las **props** son de **solo lectura**. Un componente **nunca** debe modificar `props.nombre = 'otro'`. Si necesita cambiar algo, lo hace con `useState` (paso 4).

#### 1.4.3. Ejemplo aplicado a nuestro proyecto

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Mire el archivo `src/views/common/LoadingSpinner.jsx` del esqueleto del Paso 3:

```jsx
// src/views/common/LoadingSpinner.jsx
const LoadingSpinner = () => {
  return (
    <div className="spinner-container">
      <div className="spinner"></div>
      <p>Cargando...</p>
    </div>
  )
}

export default LoadingSpinner
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Análisis línea por línea:**

| Línea                                   | ¿Qué hace?                                                        |
| --------------------------------------- | ----------------------------------------------------------------- |
| `const LoadingSpinner = () => {`        | Declara un componente funcional (arrow function) con mayúscula    |
| `return (`                              | Inicia el retorno del JSX                                         |
| `<div className="spinner-container">`   | Elemento raíz del componente (un solo `<div>`)                    |
| `<div className="spinner"></div>`       | Elemento interno: el círculo que girará con CSS                   |
| `<p>Cargando...</p>`                    | Texto visible                                                      |
| `</div>`                                | Cierra el elemento raíz                                            |
| `)`                                     | Cierra el paréntesis del `return`                                  |
| `}`                                     | Cierra el cuerpo de la función                                     |
| `export default LoadingSpinner`         | Exporta el componente para que `App.jsx` pueda importarlo          |

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Observe:** este componente **no recibe props** (no hay `{ props }` en los paréntesis), porque no necesita datos externos. Solo pinta un spinner estático.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Observe también:** usa `className` en lugar de `class`. En JSX, `class` es una palabra reservada de JavaScript, así que React usa `className`.

## 1.5. El componente raíz de nuestro proyecto

#### 1.5.1. ¿Dónde arranca todo?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En el Paso 3 creamos este esqueleto. El **punto de entrada** es `src/main.jsx`:

```jsx
// src/main.jsx (esqueleto del Paso 3, todavía sin BrowserRouter)
import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App.jsx'
import './App.css'
import './styles/common.css'

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
)
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Análisis línea por línea:**

| Línea                                                | ¿Qué hace?                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------ |
| `import React from 'react'`                          | Importa React (necesario para `StrictMode`)                        |
| `import ReactDOM from 'react-dom/client'`            | Importa el renderizador de React para el navegador                 |
| `import App from './App.jsx'`                        | Importa el componente raíz                                         |
| `import './App.css'`                                 | Importa estilos globales                                           |
| `ReactDOM.createRoot(document.getElementById('root'))` | Le dice a React: "vas a vivir dentro del `<div id="root">`"      |
| `.render(<React.StrictMode><App /></React.StrictMode>)` | Renderiza `<App />` envuelto en `StrictMode` (doble render en dev para detectar bugs) |

#### 1.5.2. ¿Y de dónde sale el `<div id="root">`?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Del archivo `index.html` (creado por Vite):

```html
<body>
  <div id="root"></div>
  <script type="module" src="/src/main.jsx"></script>
</body>
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Flujo completo:** el navegador carga `index.html` → el `<script>` ejecuta `main.jsx` → `main.jsx` monta `<App />` dentro de `<div id="root">` → a partir de ahí, **todo lo que se ve** es un árbol de componentes.

#### 1.5.3. El componente `App`

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En el esqueleto del Paso 3, `App.jsx` es este:

```jsx
// src/App.jsx
function App() {
  return (
    <div>
      <h1>Sistema de Información Web</h1>
      <p>Configuración inicial completada</p>
    </div>
  )
}

export default App
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Es el componente raíz** de toda la aplicación. En el paso 8 (React Router) lo convertiremos en el que define las **rutas** entre `Login`, `Register` y `Dashboard`.

## 1.8. 🚨 Solución de problemas comunes

#### 1.8.1. "No entiendo por qué React si HTML ya funciona"

**Problema:** Es la duda más común en la primera clase.

**Solución:** Piense en React como **"HTML que se actualiza solo cuando los datos cambian"**. Si su HTML nunca cambia (una página estática), React no aporta mucho. Pero si su pantalla **reacciona** al usuario (login, listas, formularios), React le ahorra **decenas de líneas** de manipulación manual del DOM.

#### 1.8.2. "¿Puedo mezclar React con JS clásico?"

**Problema:** Viene de un curso anterior y quiere usar `document.getElementById`.

**Solución:** Técnicamente sí, pero **no lo haga en este curso**. React maneja el DOM por usted. Si mezcla los dos enfoques, tendrá bugs difíciles de rastrear (React puede borrar lo que usted insertó a mano). En el Capítulo IV (Node + Express) veremos que el patrón es: React maneja la **UI**, los servicios (`httpService`, `storageService`) manejan **datos**.

#### 1.8.3. "El componente no aparece en pantalla"

**Problema:** Escribió un componente pero no se ve.

**Solución:** Un componente no se renderiza solo. Tiene que estar **importado y usado** desde otro componente (directa o indirectamente desde `App`). Si creó `MiComponente.jsx` pero nadie lo importa, no se verá. **Regla:** todo componente debe estar alcanzable desde el árbol de `App`.

#### 1.8.4. "Error: `React` must be in scope when using JSX"

**Problema:** Se olvidó importar `React` en un archivo `.jsx`.

**Solución:** Con React 17+ y la nueva transformación automática de JSX, ya **no** es obligatorio importar `React` para usar JSX. Pero `main.jsx` **sí lo necesita** porque usa `React.StrictMode`. Si ve este error, agregue `import React from 'react'` al inicio del archivo problemático.

#### 1.8.5. "Error: Adjacent JSX elements must be wrapped in an enclosing tag"

**Problema:** El `return` devuelve dos o más elementos raíz.

**Solución:** Envuélvalos en `<div>…</div>` o en un **fragmento** `<>…</>`. Ver sección 1.4.2, Regla 2.
