### 📚 Explicación
> En este paso vamos a **construir el esqueleto completo** de la aplicación. Antes de escribir una sola línea de lógica, necesitamos entender **cómo se organiza un proyecto React profesional** usando el patrón **MVC (Modelo – Vista – Controlador)** y luego crear las carpetas y los archivos (vacíos) que usarán los capítulos siguientes.
>
> El proyecto sigue una **arquitectura MVC adaptada a React**, donde:
> - **Model** → habla con la API (HTTP, storage, JWT).
> - **Controller** → contiene la lógica de negocio y validaciones.
> - **View** → componentes de React que renderizan el HTML.
> - **Hook** → puente entre Controller y View (patrón moderno de React).
>
> Esto nos permite tener el código **organizado, testeable y fácil de migrar** de una API falsa (JSON Server) a una API real (Node.js + Express) sin tocar las vistas.

## 3.1. Patrón Arquitectónico (MVC en React)

#### 3.1.1. ¿Qué es MVC?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **MVC** = **M**odel – **V**iew – **C**ontroller. Es un patrón de diseño que **separa responsabilidades**.

| Capa           | Responsabilidad                                         | En nuestro proyecto vive en… |
| -------------- | ------------------------------------------------------- | ---------------------------- |
| **Model**      | Comunicación con datos (API, storage, JWT)              | `src/models/` y `src/services/` |
| **Controller** | Lógica de negocio, validaciones, coordinación           | `src/controllers/`            |
| **View**       | Interfaz de usuario (lo que se ve en el navegador)      | `src/views/`                  |
| **Hook**       | Adaptador entre Controller y View (estado de React)     | `src/hooks/`                  |

#### 3.1.2. ¿Cómo se aplica MVC a React?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; React **no es MVC puro** (es basado en componentes). Pero podemos organizar el código para que **respete MVC**:

```
┌────────────────────────────────────────────────────────────┐
│                    COMPONENTE (View)                       │
│  - Solo se encarga de renderizar JSX                       │
│  - No sabe de fetch, ni de localStorage, ni de validaciones│
└─────────────────────────┬──────────────────────────────────┘
                          │ usa
                          ▼
┌────────────────────────────────────────────────────────────┐
│                    HOOK (useAuth, useUsers…)               │
│  - Maneja el estado de React (useState, useEffect)         │
│  - Llama al Controller                                     │
└─────────────────────────┬──────────────────────────────────┘
                          │ llama
                          ▼
┌────────────────────────────────────────────────────────────┐
│                  CONTROLLER (AuthController…)              │
│  - Validaciones de negocio                                 │
│  - Orquesta llamadas al Model                              │
└─────────────────────────┬──────────────────────────────────┘
                          │ usa
                          ▼
┌────────────────────────────────────────────────────────────┐
│                    MODEL (AuthModel, UserModel…)           │
│  - Llama al servicio HTTP                                  │
│  - Guarda/lee token y usuario                              │
└─────────────────────────┬──────────────────────────────────┘
                          │ usa
                          ▼
┌────────────────────────────────────────────────────────────┐
│              SERVICES (httpService, storageService…)       │
│  - Wrappers de bajo nivel (fetch, localStorage, JWT)       │
└────────────────────────────────────────────────────────────┘
```

#### 3.1.3. ¿Por qué usar MVC en React?

| Ventaja                            | Explicación                                                    |
| ---------------------------------- | -------------------------------------------------------------- |
| **Separación de responsabilidades**| Cada archivo hace una sola cosa                                |
| **Testeabilidad**                  | Podemos probar el Model sin renderizar componentes             |
| **Migración sencilla**             | Cambiar JSON Server por Node+Express solo toca Model y Services|
| **Reutilización**                  | La misma lógica se puede usar en varias vistas                 |
| **Trabajo en equipo**              | Cada desarrollador sabe dónde buscar                           |

## 3.2. Estructura de Carpetas y Archivos

#### 3.2.1. Estructura objetivo del proyecto

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Esta es la estructura **completa** que tendrá el proyecto al final del curso:

```bash
frontend_web/
├── public/                        # Archivos estáticos
├── src/
│   ├── assets/                    # Recursos (imágenes, fuentes)
│   │
│   ├── config/                    # ⚙️ Configuración global
│   │   ├── api.js                 # URLs y endpoints de la API
│   │   ├── constants.js           # Constantes globales
│   │   └── routes.js              # Rutas de la app
│   │
│   ├── services/                  # 🔌 Servicios de bajo nivel
│   │   ├── httpService.js         # Wrapper de fetch
│   │   ├── storageService.js      # Wrapper de localStorage
│   │   └── jwtService.js          # Utilidades JWT
│   │
│   ├── models/                    # 🗄️ MODELO (acceso a datos)
│   │   ├── AuthModel.js
│   │   ├── UserModel.js
│   │   └── DashboardModel.js
│   │
│   ├── controllers/               # 🎮 CONTROLADOR (lógica de negocio)
│   │   ├── AuthController.js
│   │   ├── UserController.js
│   │   └── DashboardController.js
│   │
│   ├── hooks/                     # 🪝 HOOKS (puente Controller ↔ View)
│   │   ├── useAuth.js
│   │   ├── useUsers.js
│   │   └── useDashboard.js
│   │
│   ├── views/                     # 👁️ VISTA (componentes React)
│   │   ├── auth/
│   │   │   ├── LoginView.jsx
│   │   │   └── RegisterView.jsx
│   │   ├── common/
│   │   │   ├── AlertMessage.jsx
│   │   │   ├── LoadingSpinner.jsx
│   │   │   └── Navbar.jsx
│   │   ├── dashboard/
│   │   │   ├── DashboardView.jsx
│   │   │   ├── DashboardHeader.jsx
│   │   │   ├── DashboardStats.jsx
│   │   │   ├── UsersView.jsx
│   │   │   ├── UserForm.jsx
│   │   │   └── UserDetails.jsx
│   │   └── layouts/
│   │       └── MainLayout.jsx
│   │
│   ├── styles/                    # 🎨 Estilos CSS por vista
│   │   ├── common.css
│   │   ├── Dashboard.css
│   │   ├── Login.css
│   │   ├── Navbar.css
│   │   ├── Register.css
│   │   └── Users.css
│   │
│   ├── utils/                     # 🧰 Utilidades genéricas
│   │   ├── helpers.js
│   │   └── validators.js
│   │
│   ├── App.css
│   ├── App.jsx                    # 🚪 Componente raíz con rutas
│   ├── index.css
│   └── main.jsx                   # 🚀 Punto de entrada
│
├── .gitignore
├── eslint.config.js
├── index.html
├── package.json
├── package-lock.json
├── README.md
└── vite.config.js
```

#### 3.2.2. Regla mnemotécnica para recordar la estructura

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **"C‑S‑M‑C‑H‑V"** (Config, Services, Models, Controllers, Hooks, Views):

| Letra | Carpeta      | Se pregunta…                                  |
| ----- | ------------ | --------------------------------------------- |
| **C** | `config/`    | ¿Dónde está la URL de la API?                 |
| **S** | `services/`  | ¿Cómo hago fetch o guardo en localStorage?    |
| **M** | `models/`    | ¿Qué datos necesito y de dónde los saco?      |
| **C** | `controllers/`| ¿Qué reglas de negocio aplico?               |
| **H** | `hooks/`     | ¿Cómo expongo eso a los componentes?          |
| **V** | `views/`     | ¿Qué se ve en pantalla?                       |

## 3.3. Creación de Carpetas

#### 3.3.1. Ubicarse en la carpeta del proyecto

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Abrir la terminal integrada de VS Code (`CTRL + SHIFT + Ñ`) y navegar a `frontend_web/`:

```powershell
cd frontend_web/
```

#### 3.3.2. Crear la carpeta principal `src` (si no existe)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Vite ya la crea en el Paso 2, pero por seguridad:

```powershell
mkdir src -Force
```

#### 3.3.3. Crear todas las carpetas de la arquitectura MVC

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Ejecutar **un solo comando** para crear todas las carpetas dentro de `src/`:

```powershell
# Carpetas principales
mkdir src\config, src\services, src\models, src\controllers, src\hooks, src\views, src\styles, src\utils -Force

# Subcarpetas de views/
mkdir src\views\auth, src\views\common, src\views\dashboard, src\views\layouts -Force
```

#### 3.3.4. Verificar la estructura creada

```powershell
tree src /F
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; La salida debe mostrar (sin contar los archivos base de Vite):

```bash
src
├── assets
├── config
├── controllers
├── hooks
├── models
├── services
├── styles
├── utils
└── views
    ├── auth
    ├── common
    ├── dashboard
    └── layouts
```

> 💡 **Atajo alternativo (PowerShell 7+):** si tienes PowerShell 7 puedes usar `mkdir src/{config,services,models,controllers,hooks,views,styles,utils}` — pero el comando largo funciona en cualquier versión.

## 3.6. 🚨 Solución de problemas comunes

#### 3.6.1. Error: "mkdir: cannot create directory … File exists"

**Problema:** La carpeta ya existía (Vite crea algunas por defecto).

**Solución:** Es normal — con `-Force` en PowerShell el comando ignora el conflicto. Si usas `cmd`, agrega `2>nul` al final para silenciar el error.

#### 3.6.2. `New-Item` no está disponible

**Problema:** Estás usando **cmd.exe** y no PowerShell.

**Solución:** Cambia a PowerShell:

```powershell
powershell
```

O crea los archivos manualmente desde VS Code: clic derecho sobre la carpeta → **New File**.

#### 3.6.3. `tree` no muestra las carpetas creadas

**Problema:** Estás en la carpeta equivocada (no estás dentro de `frontend_web/`).

**Solución:** Verifica con `pwd` (PowerShell) o `cd` (cmd) que estás en la carpeta correcta antes de correr `tree`.

#### 3.6.4. Los archivos `.jsx` aparecen con otro color en VS Code

**Problema:** VS Code no reconoce `.jsx` como JavaScript React.

**Solución:** Instala la extensión **"ES7+ React/Redux/React-Native snippets"** (del Paso 1) — con ella, el resaltado y los snippets `rafce` funcionan correctamente.

#### 3.6.5. ESLint marca "empty file"

**Problema:** Algunos archivos `.js` quedaron **realmente vacíos** (sin el comentario `// TODO`).

**Solución:** Aplica el truco de la sección **3.4.9** para agregar el comentario placeholder a todos los archivos.

#### 3.6.6. Al escribir `mkdir src\config, src\services, …` PowerShell da error

**Problema:** Estás usando **cmd** en vez de **PowerShell**, o la coma no se interpreta igual.

**Solución:** Ejecutar un `mkdir` por carpeta, o cambiar a PowerShell:

```powershell
mkdir src\config -Force
mkdir src\services -Force
mkdir src\models -Force
# ...
```
