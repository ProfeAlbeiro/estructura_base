## 3.1. ¿Qué es un componente funcional?

#### 3.1.1. Definición

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Un **componente funcional** es una **función de JavaScript** que:

1. Recibe **props** como argumento (opcional).
2. Devuelve **JSX**.
3. Tiene un **nombre con mayúscula inicial**.

```jsx
function Saludo(props) {
  return <h1>Hola, {props.nombre}</h1>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; También se puede escribir con **arrow function** (el estilo del proyecto `sis-web-mvc`):

```jsx
const Saludo = (props) => {
  return <h1>Hola, {props.nombre}</h1>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Ambas formas son equivalentes.** El proyecto original usa arrow functions en todos los componentes, así que mantendremos ese estilo.

#### 3.1.2. ¿Qué pasó con los componentes de clase?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Antes de 2019, los componentes se escribían con `class extends React.Component`:

```jsx
// ❌ Estilo antiguo (componente de clase)
class Saludo extends React.Component {
  render() {
    return <h1>Hola, {this.props.nombre}</h1>
  }
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Con la llegada de los **Hooks** en React 16.8 (2019), los componentes funcionales pueden tener estado y efectos, por lo que **los componentes de clase quedaron obsoletos**.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Regla del curso:** use siempre **componentes funcionales**. Si encuentra un tutorial con clases, está desactualizado.

#### 3.1.3. Los 3 estilos de declaración

| Estilo                          | Ejemplo                                                    | Cuándo usarlo                          |
| ------------------------------- | ---------------------------------------------------------- | -------------------------------------- |
| **Function declaration**        | `function Saludo() { … }`                                  | Componentes que se exportan por nombre |
| **Arrow function con bloque**   | `const Saludo = () => { return … }`                        | Estilo del proyecto original ✅        |
| **Arrow function con retorno implícito** | `const Saludo = () => <h1>Hola</h1>`                | Componentes de una sola línea           |

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **El proyecto `sis-web-mvc` usa el segundo estilo** (arrow function con bloque). Lo mantendremos así para que sea consistente con el código original.

#### 3.1.4. Diferencia entre componente y elemento

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Componente:** la **función** que define qué renderizar.

```jsx
const Saludo = (props) => <h1>Hola, {props.nombre}</h1>  // ← componente
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Elemento:** el **resultado** de invocar esa función con JSX.

```jsx
<Saludo nombre="María" />  // ← elemento (invoca el componente)
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Analogía:** el componente es la **receta**, el elemento es el **plato servido**. Cuando React ve `<Saludo nombre="María" />`, ejecuta la función `Saludo` con `props = { nombre: 'María' }` y obtiene `<h1>Hola, María</h1>`.

## 3.2. Props: los argumentos del componente

#### 3.2.1. Definición

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Props** (properties) son los **datos que un componente padre le pasa a un componente hijo**.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Se pasan **como atributos** en el JSX del componente hijo:

```jsx
<Saludo nombre="María" edad={25} />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; El hijo las recibe en un **objeto único** llamado `props`:

```jsx
const Saludo = (props) => {
  // props = { nombre: 'María', edad: 25 }
  return (
    <div>
      <h1>Hola, {props.nombre}</h1>
      <p>Tienes {props.edad} años</p>
    </div>
  )
}
```

#### 3.2.2. ¿Cómo se pasan las props? (3 formas)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Forma 1: string literal** (sin llaves, para texto)

```jsx
<Saludo nombre="María" />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Forma 2: expresión JavaScript** (con llaves, para números, booleanos, objetos, variables)

```jsx
const edad = 25
<Saludo nombre="María" edad={edad} esAdmin={true} />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Forma 3: shorthand** (cuando la variable se llama igual que la prop)

```jsx
const nombre = 'María'
<Saludo nombre={nombre} />   // ← largo
<Saludo nombre={nombre} />   // ← se puede simplificar a:
<Saludo nombre={nombre} />   // ← hmm, no. La forma corta es:
<Saludo nombre />            // ← esto pasa nombre={true}, NO lo que queremos
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Corrección:** el shorthand `<Saludo nombre />` equivale a `<Saludo nombre={true} />`. **No** es lo que queremos para pasar strings. Para variables se usa siempre `{variable}`.

#### 3.2.3. Tipos de datos que se pueden pasar

| Tipo            | Ejemplo JSX                          | Cómo lo recibe el hijo         |
| --------------- | ------------------------------------ | ------------------------------ |
| **String**      | `<C nombre="María" />`               | `props.nombre === 'María'`     |
| **Número**      | `<C edad={25} />`                    | `props.edad === 25`            |
| **Booleano**    | `<C activo={true} />`                | `props.activo === true`        |
| **Objeto**      | `<C usuario={{ id: 1 }} />`          | `props.usuario.id === 1`       |
| **Array**       | `<C items={['a', 'b']} />`           | `props.items[0] === 'a'`       |
| **Función**     | `<C onClick={() => {}} />`           | `props.onClick` es función     |
| **JSX**         | `<C icono={<span>★</span>} />`       | `props.icono` es un elemento   |
| **Componente**  | `<C Icono={MiIcono} />`              | `props.Icono` es una función   |

#### 3.2.4. ¿Por qué son inmutables?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Las props son de solo lectura.** Si el hijo intenta modificar `props.nombre`, React lanza este warning:

```
Warning: Cannot assign to read only property 'nombre' of object '#<Object>'
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **¿Por qué?** Porque el **padre es el dueño** del dato. Si el hijo pudiera modificarlo, el padre y el hijo tendrían visiones distintas del mismo dato → bugs difíciles de rastrear.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Regla:** si el hijo necesita modificar un dato, el padre le pasa una **función** (callback) que el hijo invoca. El padre decide qué hacer con el cambio. Veremos esto en el paso 6 (eventos).

## 3.3. Desestructuración de props

#### 3.3.1. ¿Qué es la desestructuración?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Es una **característica de JavaScript** que permite **extraer propiedades de un objeto** en variables individuales.

```javascript
// Sin desestructuración
const nombre = props.nombre
const edad = props.edad

// Con desestructuración
const { nombre, edad } = props
```

#### 3.3.2. Aplicada a props (la forma moderna)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Sin desestructuración** (estilo antiguo):

```jsx
const Saludo = (props) => {
  return <h1>Hola, {props.nombre}</h1>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Con desestructuración** (estilo moderno, **preferido**):

```jsx
const Saludo = ({ nombre }) => {
  return <h1>Hola, {nombre}</h1>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Con valores por defecto:**

```jsx
const Saludo = ({ nombre = 'Invitado', edad = 0 }) => {
  return <h1>Hola, {nombre} ({edad} años)</h1>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Con múltiples props:**

```jsx
const Usuario = ({ nombre, email, rol = 'user' }) => {
  return (
    <div>
      <h2>{nombre}</h2>
      <p>{email}</p>
      <span>{rol}</span>
    </div>
  )
}
```

#### 3.3.3. ¿Por qué desestructurar?

| Ventaja                              | Explicación                                              |
| ------------------------------------ | -------------------------------------------------------- |
| **Más legible**                      | Escribes `nombre` en vez de `props.nombre` 10 veces      |
| **Autodocumentado**                  | La firma del componente muestra **qué props espera**     |
| **Valores por defecto**              | Puedes asignar default en la misma línea                 |
| **Menos errores de tipeo**           | Al no repetir `props.`, hay menos oportunidad de error   |

#### 3.3.4. Regla del curso

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Siempre desestructuramos props** en la firma del componente:

```jsx
// ❌ Evitar
const MiComponente = (props) => { … }

// ✅ Preferir
const MiComponente = ({ prop1, prop2 }) => { … }
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Excepción:** si el componente recibe **muchísimas** props y no las va a usar todas, a veces es más limpio dejar `props` y acceder solo a las que necesita. Pero en este curso, con componentes pequeños, desestructuramos siempre.

#### 3.3.5. Desestructuración anidada (avanzado)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Si un prop es un objeto y solo necesitas una propiedad:

```jsx
const Usuario = ({ usuario: { nombre, email } }) => {
  return <h1>{nombre} - {email}</h1>
}

// Uso: <Usuario usuario={{ nombre: 'Ana', email: 'ana@x.com' }} />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **No abusar** de la desestructuración anidada — pierde legibilidad rápido. Preferible:

```jsx
const Usuario = ({ usuario }) => {
  const { nombre, email } = usuario  // ← más claro
  return <h1>{nombre} - {email}</h1>
}
```

## 3.4. Props especiales: `children`

#### 3.4.1. ¿Qué es `children`?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **`children`** es una prop **especial** que React inyecta automáticamente cuando un componente **envuelve** contenido entre sus etiquetas.

```jsx
<MiComponente>
  <h1>Hola</h1>          {/* ← esto es children */}
  <p>Mundo</p>           {/* ← esto también es children */}
</MiComponente>
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; El componente `MiComponente` recibe ese contenido en `props.children`:

```jsx
const MiComponente = ({ children }) => {
  return <div className="wrapper">{children}</div>
}
```

#### 3.4.2. ¿Para qué sirve?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Para crear **componentes contenedores** o **layouts** que se usan así:

```jsx
<Card>
  <h2>Título</h2>
  <p>Contenido de la tarjeta</p>
</Card>
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; El componente `Card` puede aplicar estilos comunes (borde, sombra, padding) sin importar el contenido interno:

```jsx
const Card = ({ children }) => {
  return <div className="card">{children}</div>
}
```

#### 3.4.3. `children` en nuestro proyecto

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En el esqueleto del Paso 3 creamos `src/views/layouts/MainLayout.jsx`:

```jsx
// src/views/layouts/MainLayout.jsx
const MainLayout = ({ children }) => {
  return <div className="main-layout">{children}</div>
}

export default MainLayout
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Ese `{children}`** es la prop especial. `MainLayout` se usará así en pasos posteriores:

```jsx
<MainLayout>
  <Navbar />
  <DashboardView />
</MainLayout>
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; `Navbar` y `DashboardView` se renderizarán **dentro** del `<div className="main-layout">`.

#### 3.4.4. `children` puede ser cualquier cosa

| Tipo de `children`         | Ejemplo                                          |
| -------------------------- | ------------------------------------------------ |
| **String**                 | `<Card>Hola</Card>`                              |
| **JSX**                    | `<Card><h1>Hola</h1></Card>`                     |
| **Array de JSX**           | `<Card><h1>A</h1><p>B</p></Card>`                |
| **Componente**             | `<Card><Navbar /></Card>`                        |
| **Función** (render prop)  | `<Card>{(x) => <p>{x}</p>}</Card>` (avanzado)    |
| **Nada (undefined)**       | `<Card />`                                       |

#### 3.4.5. `React.Children` (utilidad)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Si necesitas manipular `children` (contar, mapear), React ofrece `React.Children`:

```jsx
import React from 'react'

const Lista = ({ children }) => {
  const count = React.Children.count(children)
  return (
    <div>
      <p>Hay {count} hijos</p>
      {children}
    </div>
  )
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **No lo usaremos en este curso**, pero conviene saber que existe.

## 3.5. Composición de componentes

#### 3.5.1. ¿Qué es componer?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Componer** = construir componentes **usando otros componentes** como bloques.

```jsx
const Boton = ({ texto, onClick }) => (
  <button onClick={onClick}>{texto}</button>
)

const Formulario = () => (
  <form>
    <Boton texto="Guardar" onClick={() => {}} />
    <Boton texto="Cancelar" onClick={() => {}} />
  </form>
)
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; `Formulario` **compone** dos `Boton`. Cada `Boton` es independiente.

#### 3.5.2. Composición vs herencia

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; React **no usa herencia** (no hay `extends`). Usa **composición**.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Si dos componentes comparten lógica, **no** se crea un padre común con herencia. En su lugar:

- Se extrae la lógica común a un **hook personalizado** (`useAuth`, `useUsers`…).
- O se pasa la lógica común como **prop** (función).
- O se envuelve con un **componente contenedor** (HOC o `children`).

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Frase típica de la comunidad React:** *"Composition over inheritance"* (composición sobre herencia).

#### 3.5.3. Ejemplo: composición con `children`

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Un `Modal` genérico:

```jsx
const Modal = ({ titulo, children, onClose }) => {
  return (
    <div className="modal-overlay" onClick={onClose}>
      <div className="modal-content" onClick={(e) => e.stopPropagation()}>
        <div className="modal-header">
          <h3>{titulo}</h3>
          <button onClick={onClose}>×</button>
        </div>
        <div className="modal-body">{children}</div>
      </div>
    </div>
  )
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Se usa así:

```jsx
<Modal titulo="Confirmar" onClose={() => setShow(false)}>
  <p>¿Estás seguro?</p>
  <button>OK</button>
</Modal>
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **`Modal` no sabe** qué contiene el body. Solo se encarga del overlay, header y estilos. El contenido viene como `children`.

#### 3.5.4. La analogía del LEGO

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Cada componente es una **pieza de LEGO**. Puedes combinarlas para hacer estructuras cada vez más grandes.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Un `Boton` es una pieza pequeña. Un `Formulario` que tiene 3 botones es una pieza mediana. Un `LoginView` que tiene un `Formulario` y 2 `AlertMessage` es una pieza grande. Un `App` que tiene `Navbar` + `LoginView` + `DashboardView` es la estructura completa.

## 3.6. Reglas de las props

#### 3.6.1. Regla 1: las props son inmutables

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Nunca** modificar una prop directamente:

```jsx
// ❌ Incorrecto
const Saludo = ({ nombre }) => {
  nombre = 'Otro'  // ← warning
  return <h1>{nombre}</h1>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Solución:** usar `useState` si el valor va a cambiar (paso 4).

#### 3.6.2. Regla 2: pasar callbacks para modificar datos del padre

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Si el hijo necesita **notificar** un cambio al padre, el padre le pasa una **función**:

```jsx
// Padre
const Padre = () => {
  const [nombre, setNombre] = useState('María')
  return <Hijo nombre={nombre} onCambiarNombre={setNombre} />
}

// Hijo
const Hijo = ({ nombre, onCambiarNombre }) => (
  <div>
    <p>{nombre}</p>
    <button onClick={() => onCambiarNombre('Pedro')}>
      Cambiar
    </button>
  </div>
)
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **El hijo no modifica `nombre`.** Llama a `onCambiarNombre('Pedro')` y el **padre** decide si actualiza el estado.

#### 3.6.3. Regla 3: nombres de props en camelCase

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Igual que los atributos HTML, las props personalizadas van en **camelCase**:

```jsx
// ❌ Incorrecto
<MiComponente mi-prop="valor" />

// ✅ Correcto
<MiComponente miProp="valor" />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Excepción:** los atributos `data-*` y `aria-*` mantienen kebab-case:

```jsx
<button data-testid="submit-btn" aria-label="Enviar">OK</button>
```

#### 3.6.4. Regla 4: las props pueden tener valores por defecto

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En la firma del componente:

```jsx
const Boton = ({ texto = 'Enviar', color = 'azul' }) => {
  return <button style={{ color }}>{texto}</button>
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En el JSX del padre (menos común):

```jsx
<Boton texto="Guardar" />           {/* color = 'azul' por defecto */}
<Boton texto="Cancelar" color="rojo" />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Recomendación:** definir defaults en la firma del hijo (más legible).

#### 3.6.5. Regla 5: usar PropTypes o TypeScript (opcional)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En JavaScript puro, puede declarar los tipos esperados con `propTypes`:

```jsx
import PropTypes from 'prop-types'

const Saludo = ({ nombre, edad }) => (
  <h1>{nombre} ({edad})</h1>
)

Saludo.propTypes = {
  nombre: PropTypes.string.isRequired,
  edad: PropTypes.number
}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **En este curso no usamos PropTypes.** Si en el futuro migra a TypeScript, los tipos se declaran en la firma:

```typescript
// TypeScript (referencia)
const Saludo = ({ nombre, edad }: { nombre: string; edad?: number }) => (
  <h1>{nombre} ({edad})</h1>
)
```

#### 3.6.6. Regla 6: no pasar objetos inline (rendimiento)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Cada render crea un objeto nuevo → re-render innecesario:

```jsx
// ⚠️ Objeto nuevo en cada render
<MiComponente config={{ color: 'red' }} />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Solución:** memoizar con `useMemo` (paso 10) o definir el objeto fuera del render:

```jsx
const CONFIG = { color: 'red' }

const Padre = () => <MiComponente config={CONFIG} />
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **No es un problema en este paso** — se menciona solo para que sepa que existe. Lo veremos con `useMemo` en el paso 10.

## 3.7. Práctica guiada: refactorizar el Login con componentes

> 🎯 **Objetivo:** reemplazar los `<p>Vista en construcción...</p>` por **componentes reales con props**: `AlertMessage` y `LoadingSpinner`. Verá cómo las props permiten **reutilizar** un componente en distintos contextos.

#### 3.7.1. Actualizar `src/views/common/AlertMessage.jsx`

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Modifica el archivo con este contenido:

```jsx
// src/views/common/AlertMessage.jsx
const AlertMessage = ({ type = 'info', message }) => {
  if (!message) return null
  return <div className={`alert alert-${type}`}>{message}</div>
}

export default AlertMessage
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Análisis:**

| Parte                           | ¿Qué hace?                                                       |
| ------------------------------- | ---------------------------------------------------------------- |
| `({ type = 'info', message })`  | Desestructura props con default `'info'`                         |
| `if (!message) return null`     | Si no hay mensaje, no renderiza nada (early return)              |
| `` className={`alert alert-${type}`} `` | Template literal: une `alert` con la clase del tipo     |
| `{message}`                     | Renderiza el texto del mensaje                                    |

#### 3.7.2. Actualizar `src/views/auth/LoginView.jsx` (con componentes y props)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Sin mirar la solución**, responda:

1. ¿Qué diferencia hay entre `<MiComponente />` y `MiComponente()`?
2. ¿Qué pasa si en `LoginView.jsx` pongo `loading = "false"` (como string en vez de booleano)?
3. ¿Por qué `<AlertMessage type="error" message={error} />` no renderiza nada si `error = ''`?
4. ¿Qué significa el shorthand `<MiComponente activo />`?
5. ¿Qué pasa si intento modificar `props.nombre = 'Otro'` dentro del hijo?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Respuestas** (no mire hasta intentarlo):

1. `<MiComponente />` es un **elemento** (React lo ejecuta cuando renderiza). `MiComponente()` es una **llamada directa a la función** (no recomendado, porque React no puede rastrear su ciclo de vida).
2. `loading` como string `"false"` es **truthy** en JavaScript, así que el botón se deshabilitaría y el spinner aparecería. **Siempre use booleanos reales** con `{}` en JSX.
3. Porque `AlertMessage` tiene `if (!message) return null` — un string vacío es falsy, así que no renderiza.
4. `<MiComponente activo />` es equivalente a `<MiComponente activo={true} />` (shorthand solo para booleanos).
5. React lanza un **warning**: `Cannot assign to read only property`. Las props son inmutables.

## 3.9. 🚨 Solución de problemas comunes

#### 3.9.1. Error: `Cannot read properties of undefined (reading 'nombre')`

**Problema:** El componente recibe una prop que no se pasó y la usa sin default.

**Solución:** Agregar valor por defecto en la desestructuración: `({ nombre = 'Invitado' })`, o usar optional chaining: `props.nombre?.toUpperCase()`.

#### 3.9.2. Error: `Warning: Failed prop type: The prop 'nombre' is marked as required`

**Problema:** Declaró `propTypes` y no pasó la prop.

**Solución:** En este curso no usamos `propTypes`. Si ve este warning en un proyecto ajeno, agregue la prop o márquela como opcional.

#### 3.9.3. Advertencia: `Each child in a list should have a unique "key" prop`

**Problema:** Renderizó un array de componentes sin `key`.

**Solución:** Vea el paso 2 (sección 2.3.5) — use `key={item.id}`. En este paso no hay listas, pero lo verá pronto.

#### 3.9.4. `Warning: Cannot update a component while rendering a different component`

**Problema:** Está llamando a una función de actualización de estado del padre **dentro del render** del hijo.

**Solución:** Mueva la llamada a un `useEffect` o a un manejador de eventos (`onClick`, `onChange`). Los efectos secundarios van en `useEffect` (paso 5).

#### 3.9.5. El componente no se actualiza al cambiar una prop

**Problema:** Está mutando la prop o el objeto original en lugar de crear uno nuevo.

**Solución:** En React, **nunca** mutar. Si el padre quiere actualizar el dato, debe crear un nuevo objeto/array (con spread `{ ...obj }` o `[ ...arr ]`). El estado y las props se tratan como inmutables.

#### 3.9.6. `Warning: Each child in a list should have a unique "key" prop`

**Problema:** Usó `.map()` sin `key`.

**Solución:** Agregue `key={item.id}` (o cualquier propiedad única del dato) al elemento que devuelve el `.map()`. Vea el paso 2, sección 2.3.5.

#### 3.9.7. El componente se ve pero no responde a clics

**Problema:** No ha pasado el `onClick` como prop o no lo ha conectado al botón.

**Solución:** Los eventos se pasan como props (`onClick={handleClick}`) y se conectan al elemento HTML dentro del componente hijo:

```jsx
const Boton = ({ onClick, texto }) => (
  <button onClick={onClick}>{texto}</button>
)
```

Veremos eventos en detalle en el paso 6.
