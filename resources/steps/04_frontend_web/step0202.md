## 2.1. ¿Qué es JSX?

#### 2.1.1. Definición

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **JSX** = **J**ava**S**cript **X**ML. Es una **extensión de sintaxis** que permite escribir algo **muy parecido a HTML** dentro de archivos `.jsx`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **No es HTML**, ni es un string, ni es una plantilla de texto. Es **azúcar sintáctico** para llamadas a `React.createElement`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **No la entiende el navegador directamente**. Vite (con el plugin `@vitejs/plugin-react`) la transforma a JavaScript puro **antes** de enviarla al navegador.

#### 2.1.2. ¿Por qué existe JSX?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Sin JSX**, un componente se escribiría así (Modifica el archivo `src/App.jsx`):

```javascript
// src/App.jsx
import React from 'react'
import './App.css'

// Sin JSX (válido, pero ilegible)
function App({ nombre }) {
  return React.createElement(
    'h1',
    { className: 'titulo' },
    'Hola, ',
    nombre
  )
}

export default App
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Con JSX**, el mismo componente es (Modifica el archivo `src/App.jsx`):

```jsx
// src/App.jsx
import './App.css'

// Con JSX (legible, parece HTML)
function App({ nombre }) {
  return <h1 className="titulo">Hola, {nombre}</h1>
}

export default App
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Ambos producen exactamente lo mismo en el DOM.** El JSX es solo una forma **más cómoda de escribir** lo mismo.

#### 2.1.3. ¿Qué hace Vite con el JSX?

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Cuando usted guarda un archivo `.jsx`, Vite:

1. **Detecta** que hay JSX (por la extensión `.jsx`).
2. **Transforma** cada etiqueta a `jsx()` o `jsxs()` (la versión moderna de `React.createElement`).
3. **Sirve** el JavaScript resultante al navegador.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Usted **nunca ve** este paso — pero entenderlo le ayuda a comprender por qué ciertos errores de JSX son **errores de compilación** (aparecen en la terminal antes de llegar al navegador).

#### 2.1.4. La regla fundamental

> **"JSX es una expresión de JavaScript. Puede ir en cualquier lugar donde iría un valor: una variable, un argumento, un `return`."**

```jsx
// JSX dentro de un return (lo más común)
return <h1>Hola</h1>

// JSX dentro de una variable
const titulo = <h1>Hola</h1>

// JSX dentro de una función (llamándola como etiqueta)
const render = () => <h1>Hola</h1>
```

## 2.2. JSX vs HTML: las 6 diferencias clave

> 🎯 **Esta sección es la más importante del paso.** El 90% de los errores de JSX al inicio se deben a alguna de estas 6 diferencias.

#### 2.2.1. Diferencia 1: `class` → `className`

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En HTML: `<div class="container">`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En JSX: `<div className="container">`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **¿Por qué?** `class` es una **palabra reservada** de JavaScript (la usada para declarar clases). React usa `className` para evitar el conflicto. Es el **error #1** que cometen los principiantes.

```jsx
// ❌ Incorrecto
<div class="login-card"></div>

// ✅ Correcto
<div className="login-card"></div>
```

#### 2.2.2. Diferencia 2: los atributos son `camelCase`

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En HTML: `<input maxlength="10" autocomplete="off" onchange="...">`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En JSX: `<input maxLength="10" autoComplete="off" onChange={...}>`.

| Atributo HTML     | Atributo JSX     |
| ----------------- | ---------------- |
| `class`           | `className`      |
| `for`             | `htmlFor`        |
| `maxlength`       | `maxLength`      |
| `autocomplete`    | `autoComplete`   |
| `onclick`         | `onClick`        |
| `onchange`        | `onChange`       |
| `oninput`         | `onInput`        |
| `readonly`        | `readOnly`       |
| `tabindex`        | `tabIndex`       |
| `srcset`          | `srcSet`         |

#### 2.2.3. Diferencia 3: todas las etiquetas se cierran

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En HTML, las etiquetas vacías **no** se cierran: `<input>`, `<img>`, `<br>`, `<hr>`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En JSX, **sí** se cierran: `<input />`, `<img />`, `<br />`, `<hr />`.

```jsx
// ❌ Incorrecto
<input type="email">
<img src="logo.png">

// ✅ Correcto
<input type="email" />
<img src="logo.png" />
```

> ⚠️ **Regla fácil de recordar:** en JSX, "si no tiene hijos, se cierra solo". Esto incluye `<div></div>` → se puede escribir `<div />`, pero por legibilidad se prefiere `<div></div>` cuando va a tener contenido.

#### 2.2.4. Diferencia 4: los estilos en línea son objetos

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En HTML: `style="color: red; font-size: 14px"` (un string).

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En JSX: `style={{ color: 'red', fontSize: '14px' }}` (un objeto con camelCase).

```jsx
// ❌ Incorrecto
<h1 style="color: red">Hola</h1>

// ✅ Correcto
<h1 style={{ color: 'red', fontSize: '14px' }}>Hola</h1>
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Observe las dobles llaves `{{ }}`:** la primera llave indica "voy a inyectar JavaScript", la segunda indica "empieza un objeto". Por eso son **dos pares**.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Las propiedades CSS también van en **camelCase**: `font-size` → `fontSize`, `background-color` → `backgroundColor`, `margin-top` → `marginTop`.

#### 2.2.5. Diferencia 5: comentarios entre llaves

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En HTML: `<!-- comentario -->`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En JSX **dentro del return**: `{/* comentario */}`.

```jsx
return (
  <div>
    {/* Este es un comentario JSX */}
    <h1>Hola</h1>
  </div>
)
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Fuera del return** (en la lógica del componente), los comentarios son JavaScript normal: `// ...` o `/* ... */`.

#### 2.2.6. Diferencia 6: un solo elemento raíz

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En HTML puede haber varios elementos al mismo nivel: `<h1>…</h1><p>…</p>`.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; En JSX, el `return` debe devolver **un solo elemento raíz**. Si necesita varios, use un `<div>` o un **fragmento** `<>…</>`.

```jsx
// ❌ Incorrecto: dos raíces
return (
  <h1>Título</h1>
  <p>Texto</p>
)

// ✅ Correcto: un <div> como raíz
return (
  <div>
    <h1>Título</h1>
    <p>Texto</p>
  </div>
)

// ✅ También correcto: fragmento (no añade <div> al DOM)
return (
  <>
    <h1>Título</h1>
    <p>Texto</p>
  </>
)
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **¿Cuándo usar `<div>` y cuándo `<>`?** Si necesita **estilos** (padding, margen, `display: flex`), use `<div>`. Si solo necesita **agrupar** sin afectar el layout, use `<>`.

#### 2.2.7. Tabla resumen

| # | HTML                        | JSX                              |
|---|-----------------------------|----------------------------------|
| 1 | `class="…"`                 | `className="…"`                  |
| 2 | `onclick`, `maxlength`…     | `onClick`, `maxLength`…          |
| 3 | `<input>`, `<img>`          | `<input />`, `<img />`           |
| 4 | `style="color: red"`        | `style={{ color: 'red' }}`       |
| 5 | `<!-- comentario -->`       | `{/* comentario */}`             |
| 6 | varios elementos raíz       | uno solo (o `<>…</>`)            |

## 2.3. Expresiones JavaScript dentro de JSX

#### 2.3.1. Las llaves `{}` son la puerta a JavaScript

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Dentro del JSX, **cualquier cosa entre `{}` se evalúa como JavaScript** (Modifica el archivo `src/App.jsx`).

```jsx
// src/App.jsx
import './App.css'

function App() {  
  
  const nombre = 'María'
  const edad = 25

  return (
    <div>
      <h1>Hola, {nombre}</h1>               {/* variable */}
      <p>Tienes {edad} años</p>             {/* variable */}
      <p>El año que viene: {edad + 1}</p>   {/* operación */}
      <p>Nombre en mayúsculas: {nombre.toUpperCase()}</p>  {/* método */}
    </div>
  )
}

export default App
```

#### 2.3.2. Lo que **sí** se puede poner entre `{}`

| Expresión                              | ¿Válido? |
| -------------------------------------- | -------- |
| `{variable}`                           | ✅        |
| `{objeto.propiedad}`                   | ✅        |
| `{array[0]}`                           | ✅        |
| `{a + b}`                              | ✅        |
| `{condicion ? 'sí' : 'no'}`            | ✅        |
| `{array.map(...)}`                     | ✅        |
| `{funcion()}`                          | ✅        |
| `{/* comentario */}`                   | ✅        |

#### 2.3.3. Lo que **no** se puede poner entre `{}`

| Expresión                              | ¿Válido? | Por qué                                    |
| -------------------------------------- | -------- | ------------------------------------------ |
| `{if (x) { ... }}`                     | ❌        | `if` es un **statement**, no una expresión |
| `{for (...) {...}}`                    | ❌        | `for` es un **statement**, no una expresión |
| `{const x = 1}`                        | ❌        | Es una **declaración**, no una expresión    |

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Regla:** dentro de `{}` solo va lo que **produce un valor**. Para condicionales, use el operador ternario `? :` o el operador `&&`. Para bucles, use `array.map()`.

#### 2.3.4. Condicionales en JSX: dos formas

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Forma 1: operador ternario** (cuando hay dos ramas: sí / no)

```jsx
{loading ? <LoadingSpinner /> : <LoginView />}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Forma 2: operador `&&`** (cuando solo hay una rama: "si se cumple, muéstralo")

```jsx
{error && <AlertMessage type="error" message={error} />}
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Ambas formas las usaremos en el proyecto real.** En `App.jsx` original verá `loading ? <LoadingSpinner /> : <LoginView />` y en `LoginView.jsx` verá `error && <AlertMessage … />`.

#### 2.3.5. Listas en JSX

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Para renderizar una lista, use `array.map()` y asigne una `key` única a cada elemento (Modifica el archivo `src/App.jsx`):

```jsx
// src/App.jsx
import './App.css'

function App() {  
  
  const usuarios = [
    { id: 1, nombre: 'Ana' },
    { id: 2, nombre: 'Pedro' }
  ]

  return (
    <ul>
      {usuarios.map(u => (
        <li key={u.id}>{u.nombre}</li>
      ))}
    </ul>
  )
}

export default App
```

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **La `key` es obligatoria.** React la usa para saber qué elemento cambió, se agregó o se eliminó. Sin `key`, React re-renderiza toda la lista y se pierde el estado de los hijos. Use el **ID** del dato, nunca el índice del array (a menos que la lista sea estática).

## 2.4. JSX en nuestro proyecto: análisis línea por línea

#### 2.4.1. Actualizar LoadingSpinner.jsx

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; Modifica el archivo `src/views/common/LoadingSpinner.jsx` con este contenido:

```jsx
// src/views/common/LoadingSpinner.jsx
const LoadingSpinner = () => {
  return (
    <div className="spinner-container">
      <div className="spinner"></div>
      <p>Cargando...</p>
    </div>
  )
}

export default LoadingSpinner
```

| Línea                                      | ¿Qué hace?                                                         |
| ------------------------------------------ | ------------------------------------------------------------------ |
| `const LoadingSpinner = () => {`           | Declara componente con arrow function (mayúscula inicial)          |
| `return (`                                 | Inicia el retorno                                                  |
| `<div className="spinner-container">`      | Elemento raíz, clase CSS `spinner-container` (¡`className`, no `class`!) |
| `<div className="spinner"></div>`          | Elemento interno, clase `spinner` (la animación CSS)               |
| `<p>Cargando...</p>`                       | Texto estático (no necesita `{}` porque no es una variable)         |
| `</div>`                                   | Cierra el raíz                                                     |
| `)`                                        | Cierra el `return`                                                 |
| `}`                                        | Cierra la función                                                  |
| `export default LoadingSpinner`            | Exporta el componente                                              |

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Observe:** todo es HTML "traducido" a JSX. `className` en vez de `class`. `<div>` con cierre explícito. No hay `{}` porque no hay variables.

#### 2.5.2. Análisis de las decisiones tomadas

| Elemento JSX                          | ¿Por qué se usó así?                                                    |
| ------------------------------------- | ----------------------------------------------------------------------- |
| `<div className="login-container">`   | Raíz del componente. `className`, no `class`.                           |
| `<form className="login-form">`       | Formulario HTML nativo. En el paso 6 le añadiremos `onSubmit`.          |
| `<label htmlFor="email">`             | `htmlFor` (camelCase de `for`).                                          |
| `<input … />`                         | Etiqueta vacía cerrada con `/>`.                                        |
| `autoComplete="off"`                  | `autoComplete` (camelCase de `autocomplete`).                           |
| `<button type="submit">`              | Botón de envío del formulario.                                          |
| `<strong>` + `<br />`                 | HTML normal traducido a JSX. `<br>` va cerrado como `<br />`.           |
| Texto `[la que usaste para hashear]`  | Texto literal (no es variable, va sin `{}`).                            |

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; ● &nbsp; **Observe lo que NO hicimos:** no pusimos `value` ni `onChange` en los inputs. ¿Por qué? Porque son **formularios no controlados** — todavía no sabemos manejar el estado (eso es el paso 4: `useState`). En el paso 6 los convertiremos en **formularios controlados**.

## 2.7. 🚨 Solución de problemas comunes

#### 2.7.1. Error: `Warning: Invalid DOM property 'class'. Did you mean 'className'?`

**Problema:** Usó `class` en vez de `className`.

**Solución:** Busque y reemplace `class=` por `className=` en el archivo. En VS Code: `Ctrl + H` → buscar `class=` → reemplazar `className=` → **Reemplazar todo** dentro del archivo abierto.

#### 2.7.2. Error: `Unexpected token. Did you mean {'}'} or &rbrace;?`

**Problema:** Olvidó cerrar una llave `{`.

**Solución:** Cuente las llaves del archivo. Cada `{` debe tener su `}`. En JSX anidado es fácil perder la cuenta — VS Code resalta la pareja al hacer clic sobre una llave.

#### 2.7.3. Error: `Adjacent JSX elements must be wrapped in an enclosing tag`

**Problema:** El `return` devuelve dos o más elementos raíz.

**Solución:** Envuelva en `<div>…</div>` o en `<>…</>`. Ver sección 2.2.6.

#### 2.7.4. Error: `Each child in a list should have a unique "key" prop`

**Problema:** Usó `.map()` sin `key`.

**Solución:** Agregue `key={item.id}` (o cualquier propiedad única del dato) al elemento que devuelve el `.map()`. Ver sección 2.3.5.

#### 2.7.5. Error: `Objects are not valid as a React child`

**Problema:** Intentó renderizar un objeto directamente: `<p>{usuario}</p>` donde `usuario` es `{ id: 1, nombre: 'Ana' }`.

**Solución:** Renderice **propiedades** del objeto: `<p>{usuario.nombre}</p>`. React no sabe cómo mostrar objetos enteros.

#### 2.7.6. Error: `Cannot read properties of undefined (reading 'nombre')`

**Problema:** Intentó acceder a una propiedad de algo que aún no existe (por ejemplo, un usuario que todavía no se ha cargado).

**Solución:** Use **optional chaining** `?.` o condicionales:

```jsx
<p>{usuario?.nombre}</p>
{usuario && <p>{usuario.nombre}</p>}
```

#### 2.7.7. El texto se ve raro o desalineado

**Problema:** Los archivos CSS están vacíos (correcto por ahora).

**Solución:** Es lo esperado. Los estilos completos llegan en pasos posteriores. Si desea ver algo mejor desde ya, puede pegar el contenido de `src/styles/Login.css` del proyecto original.
